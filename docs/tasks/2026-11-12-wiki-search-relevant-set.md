# [CC-1112-A] Wiki 검색 「관련 결과」 집합 — 글자 일치 + 통계 컷 (상위 200 고정 폐지)

## 배경
- 대표님 11-12: 「대시보드」 + 최신순 검색에서 11-09 이후 자료가 안 보여 「데이터가 안 쌓인다」고 오해. 실제로는 쌓이고 있었다(인덱스 3,497건, 11-09 이후 32건).
- 원인(investigator 11-12): `wiki.html` 이 의미 점수 순으로 **무조건 200건**을 잘라 관련 결과로 쓴다(`RELEVANT_TOP = 200` 364행 근처 · `REL = ranked.slice(0, 200)` 703~704행 근처 · 머리 문구 539행 근처). 이 임베딩은 무관한 글끼리도 코사인이 높고 폭이 좁다(무작위 두 노트 p50 0.768 · p90 0.818). 그래서 한 단어 검색은 무관 글 약 190건이 0.62~0.64 로 200칸을 채우고, 제목에 「대시보드」가 있는 7건은 39~176등에 흩어진다. 최신순은 그 200건 안에서만 정렬된다(`base()` 529~530 · `sorter()` 438~447 근처).
- 점수 계산은 `lib/wiki_search.js` `scoreAll`(236~259 근처: 검색어 임베딩 · 전 노트 내적 + `metaBoost` 135~147 — 태그 +0.15 · 제목 +0.10 · KNOWN_TERMS +0.10). **서버는 고치지 않는다.**
- 대표님 결정 11-12: 추천안 채택, 「더 보기(상위 200)」 버튼은 넣지 않는다.

## 범위
- 바꿀 파일: `wiki.html` 하나(관련 결과 집합 · 머리 문구). 문서: README 요약표 1행 + `docs/changelog/2026-11.md` 1항목(**MINOR** — 검색 동작 변경).
- 바꾸면 안 되는 것: `lib/wiki_search.js` · `server.js` · `wiki_lan_server.js` · 인덱스(`wiki_index.*`) · 장부 · launchd · `.env`. 정렬·필터·하이라이트 동작은 그대로.
- `wiki.html` 은 집 안 공유 서버도 그대로 쓴다 — 한 번 고치면 두 입구에 반영(서버 재시작 불필요, 새로고침).

## 단계
1. **k 실측(Gemini 임베딩 5건 — 대표님 승인 범위 안)**: 검색어 5개(대시보드 · 노션 · 클로드 코드 · 엑셀 자동화 · 영상 편집)로 로컬 서버 `/api/wiki-search?scores=1` 을 1회씩. 각각 점수 평균 μ · 표준편차 σ · 글자 일치 글들의 순위·점수를 표로. 같은 검색어를 반복 호출하지 않는다(429 면 멈추고 보고).
2. 관련 결과 집합 = **(A) 제목·태그·미리보기·채널·keywords 에 검색어 글자가 있는 글 전부**(토큰 분리는 `setHighlight` 의 규칙 재사용, 대소문자·NFC 무시) **∪ (B) 점수 ≥ μ + k·σ 인 글, 상한 50**. k 는 1단계 실측으로 정한다(출발값 2.5). 그 값과 근거를 보고에 적는다.
3. 머리 문구: 「관련도 상위 200건 안에서」 → 「글자 일치 N건 + 뜻이 가까운 M건」. 정렬(관련도·최신순 등)은 이 집합 안에서 그대로.
4. 임베딩 실패로 서버가 키워드 점수로 바뀐 경우(점수 0 제외 경로)에도 깨지지 않게 — σ=0 이거나 결과 0건이면 (A)만 쓴다.
5. 헤드리스 화면 확인(`browser-verification` 스킬 · 프로젝트 browser-guide 우선): 아래 기준표 1~3.
6. README 요약표 1행 + changelog 1항목(MINOR) · `python3 scripts/test_readme_changelog.py` · `scripts/run_all_tests.sh` · 커밋(push 는 PM).
