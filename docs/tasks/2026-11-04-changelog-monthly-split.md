## 1. 상세 37블록 → 월별 파일

- 블록 = `#### [vX.Y.Z…] - YYYY-MM-DD (…)` 줄부터 다음 `#### [v` 줄 직전(마지막 블록은 1046행)까지. **블록 본문은 한 글자도 바꾸지 않는다**(빈 줄 포함).
- 날짜의 달로 나눈다. 기대 개수: 04·1 / 05·5 / 06·1 / 07·1 / 08·4 / 09·2 / 10·20(v4.6.0-a·-b 포함) / 11·3 = 37.
- 파일 안 순서 = README 순서 그대로(이미 버전 내림차순).
- 각 파일 머리 (asset_manage `docs/changelog/2026-11.md` 본보기):
  ```
  # 변경 내역 — YYYY-MM

  요약 이력 표는 [README](../../README.md#-버전-히스토리-changelog) 에 있다. 버전 내림차순.

  ```
- 각 헤딩 **바로 윗줄**에 앵커 `<a id="vX-Y-Z"></a>` — 버전의 `.` → `-` (`v4.6.0-a` → `v4-6-0-a`, `v4.19.0` → `v4-19-0`). 앵커 줄과 헤딩 사이 빈 줄 없음.
- 헤딩 **바로 아랫줄**에 `- **요약**: <README 요약표 그 버전 행의 3번째 칸 글자 그대로>` 한 줄을 넣는다(2절). 그 아래는 원래 본문 그대로.

## 2. 요약표 → 3칸 링크

- 옛 3번째 칸(긴 요약)은 1절의 `- **요약**:` 줄로 옮겼으므로 표에서는 뺀다. 칸 글자는 바꾸지 않는다(`**…**`·`\|` 그대로).
- 새 표:
  ```
  ### 🕒 요약 이력 (Summary Table)

  | 버전 | 날짜 | 제목 |
  | :-- | :--- | :--- |
  | **[v4.19.1](docs/changelog/2026-11.md#v4-19-1)** | 2026-11-04 | **📚 상세 이력을 월별 파일로 · 요약표 3칸 · CC-1104-F** |
  | **[v4.19.0](docs/changelog/2026-11.md#v4-19-0)** | 2026-11-04 | **🏷 꿀팁 판정 글자에서 URL 빼기 · 인스타 제목·공유 파라미터** |
  …
  ```
- 제목 칸 = 그 버전 상세 헤딩의 괄호 안 글자 그대로. 글자에 `|` 가 있으면 `\|`.
- 38행(37 + v4.19.1), 버전 내림차순 = 지금 순서 + 맨 위 1행.

```

## 규칙
1. README 📝 절 = 요약 이력 표(3칸: `| **[vX.Y.Z](docs/changelog/YYYY-MM.md#vX-Y-Z)** | YYYY-MM-DD | **제목** |`, 버전 내림차순, 제목 100자 안팎) + 이 폴더 링크 목록. 상세 본문은 README 에 쓰지 않는다.
2. 한 달 한 파일(항목 1개여도 합치지 않는다). 새 항목은 맨 위. 헤딩 바로 윗줄에 `<a id="vX-Y-Z"></a>` (`.` → `-`, 접미사 `v4.6.0-a` → `v4-6-0-a`, 같은 버전이 둘이면 뒤 날짜에 `-2`).
3. 표 칸 안 `|` 는 `\|`(코드 스팬 안도). 상세가 없는 행은 링크를 만들지 않는다 — 깨진 링크 0.
4. 번호: 단일 줄 · HEAD 기준(`git log --oneline -1`) · push 한 번호는 고쳐 쓰지 않는다(옮길 때는 해시 · 원 번호를 각주로).
5. MAJOR, 또는 소스·저장소·실행 경로·예약 작업을 더하거나 빼거나 바꾸는 MINOR 는 같은 커밋에서 README 본문도 맞춘다.
6. 문서·테스트만 바꾼 커밋도 PATCH 를 올린다(v4.19.1~). `-a`·`-b` 는 새로 만들지 않는다.
7. 공개 저장소 — 개인 절대경로·맥 이름·이메일·`.env` 값을 쓰지 않는다.
```
