## 2. 설계 결정 (대표님 결정 10-14 18:46 — 바꾸지 말 것)

| 항목 | 결정 |
|---|---|
| 신호 | `PROMPT`·`RESPONSE_SCHEMA` 에 `promo_share`(NUMBER, 0~1 — 설명란·고정 댓글은 세지 않음) · `promo_subject`(BOOLEAN — 본론 자체가 제작자 자신의 유료 상품: 소개·구성·후기·고객 사례·성과) 추가, **둘 다 필수**. `promo_main` 정의 문구는 그대로 |
| 응답 검사 | `parseResponse` — `promo_subject` 가 boolean 이 아니거나 `promo_share` 가 유한한 수가 아니면 `bad_signals`(재요약은 실패 1회 → 2회면 건너뜀 · 신규는 설명란 대체 — 기존 경로). 비중은 0~1 로 자르고 소수 셋째 자리 |
| 등급 | `computeGrade` 판매 제외 = **`promo_main AND (promo_share ≥ PROMO_SHARE_MIN OR promo_subject)`**, `PROMO_SHARE_MIN = 0.5`(코드 상수, `.env` 키 없음). generic·not_ai 그대로 |
| 정의 넓히기 금지 | **promo_main 이 false 면 비중·본론과 상관없이 판매 제외 아님** — 지금(promo_main 하나로 제외)보다 항상 좁다. AND 를 OR 로 바꾸지 말 것. 두 값이 없는 옛 신호도 promo_main 만으로는 제외 안 함 |
| 로그 | promo_main true 인데 제외 안 되면 `🎬 영상 요약 (…) → keep (promo_minor 0.03)`. `computeGrade` 반환에 `note`. `why` 는 제외 사유만(그대로) |
| 장부 | `quality` 에 `promo_share`·`promo_subject` 가 같이 저장된다(신호를 펼쳐 넣는 기존 코드). **스키마 무변경(user_version 3), 장부 이전 없음** — 지금 exclude 0건, 새 규칙은 좁기만 하다 |
| 범위 밖 | 판매 구간 시각 · 기존 keep 영상 재판정 · generic·not_ai 규칙 · 30분 넘는 영상의 뒷부분(앞 30분만 본다) |
