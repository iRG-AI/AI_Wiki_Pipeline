# [CC-1108-A] 영상 입력 하루 분량 상한 10시간 시험 (`.env VIDEO_DAILY_SECONDS`)

- 작성: pm-wiki · 2026-11-08 · 승인: 대표님 11-08 「네, 시험해 봐」
- 실행: implementer · 검수: verifier

## 배경

재요약 한 주(PT 11-01~11-07) 판정: 192편, 하루 평균 27.4편. 하루 상한 40 에는 한 번도 닿지 않았고 7일 중 6일이 `daily_video_cap`(영상 입력 하루 분량 상한)으로 멈췄다.
막는 것은 3.5 Flash-Lite 모델 누계 8시간(`VIDEO_DAILY_SECONDS` 기본 28800, `lib/video_summary.js:233`). 키별 누계는 최대 약 18,600초라 걸리지 않았다.
8시간이 구글의 실제 한도인지(모델 단위인지 프로젝트 단위인지)는 모른다(CLAUDE.md 「실제 영상 요약·품질 필터」 v4.13). 상한을 10시간(36000)으로 올려 며칠 돌리고 영상 요청 429 가 나오는지 본다.
429 는 키를 돌린 뒤 그 실행에서 중단하는 경로(403 난사 아님)라 계정 위험은 낮다. 이 값은 모델 누계와 키 누계 **둘 다**에 걸린다(의도 — 코드 무변경).

## 범위

- 바꿀 것: `<REPO_ROOT>/.env` 에 한 줄 `VIDEO_DAILY_SECONDS=36000` 추가(지금은 이 키가 없다 — 기본값 사용 중).
- 바꾸면 안 되는 것: 코드 · 다른 `.env` 줄 · 운영 상태 파일(`.video_quota.json` 등) · 장부 · launchd · git 커밋(이 지시서 커밋은 시험이 끝난 뒤 PM 이 결과와 함께 한다).
- `.env` 의 다른 값을 화면·보고에 출력하지 않는다. 이 키 한 줄만 보여도 된다(비밀 아님).

## 단계

1. 백업: `cp -p .env .env.bak.20261108-video-daily` (gitignore `.env.*` 대상인지 `git check-ignore -q .env.bak.20261108-video-daily && echo ignored`).
2. 추가: `printf 'VIDEO_DAILY_SECONDS=36000\n' >> .env`
3. 확인: `grep -n '^VIDEO_DAILY_SECONDS=' .env` → 한 줄, 값 36000 · `diff <(grep -v '^VIDEO_DAILY_SECONDS=' .env) .env.bak.20261108-video-daily` → 차이 없음(출력 없음, 다른 줄 무변경).
4. 스케줄러가 읽는 값 확인(네트워크 0): `scheduler.js` 의 `loadEnv` 와 같은 방식으로 읽은 값을 찍는다 — `scheduler.js:15` `loadEnv` 를 읽고, 그 파싱 규칙대로 `VIDEO_DAILY_SECONDS` 만 출력하는 node 한 줄(다른 키 출력 금지). 기대 `36000`.
5. `git status --porcelain` → 이 지시서(`?? docs/tasks/2026-11-08-video-daily-seconds-trial.md`)와 기존 `?? .codex/` 외 변경 없음.
